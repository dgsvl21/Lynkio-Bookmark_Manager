# Lynkio - Database Design

## 1. Overview

This document describes the database architecture of Lynkio.

The system uses PostgreSQL as its primary database management system.

The database is responsible for storing:

- Users
- Bookmarks
- Collections
- Tags
- AI-generated metadata
- Future semantic search embeddings

The design follows normalization principles while remaining flexible for future expansion.

---

# 2. Database Technology

## Database Management System

PostgreSQL

Reasons for selection:

- Open source
- High reliability
- Excellent performance
- Strong community support
- Advanced indexing capabilities
- Native compatibility with pgvector

---

# 3. Database Architecture

The database follows a relational model.

Core entities:

- User
- Bookmark
- Collection
- Tag
- BookmarkTag

Future entities:

- BookmarkEmbedding
- Recommendation

---

# 4. Entity Definitions

## User

Stores registered users.

Attributes:

| Field         | Type         | Description           |
| ------------- | ------------ | --------------------- |
| id            | UUID         | Primary Key           |
| email         | VARCHAR(255) | User email            |
| password_hash | VARCHAR(255) | Hashed password       |
| created_at    | TIMESTAMP    | Account creation date |
| updated_at    | TIMESTAMP    | Last update           |

---

## Bookmark

Stores saved bookmarks.

Attributes:

| Field         | Type         | Description          |
| ------------- | ------------ | -------------------- |
| id            | UUID         | Primary Key          |
| user_id       | UUID         | Owner                |
| collection_id | UUID         | Collection           |
| url           | TEXT         | Original URL         |
| title         | VARCHAR(255) | Bookmark title       |
| summary       | TEXT         | AI-generated summary |
| notes         | TEXT         | User notes           |
| is_favorite   | BOOLEAN      | Favorite status      |
| created_at    | TIMESTAMP    | Creation date        |
| updated_at    | TIMESTAMP    | Last update          |

---

## Collection

Stores bookmark groups.

Examples:

- Programming
- University
- Personal
- Research

Attributes:

| Field       | Type         | Description          |
| ----------- | ------------ | -------------------- |
| id          | UUID         | Primary Key          |
| user_id     | UUID         | Owner                |
| name        | VARCHAR(100) | Collection name      |
| description | TEXT         | Optional description |
| created_at  | TIMESTAMP    | Creation date        |

---

## Tag

Stores tags generated by AI or users.

Attributes:

| Field | Type         | Description |
| ----- | ------------ | ----------- |
| id    | UUID         | Primary Key |
| name  | VARCHAR(100) | Tag name    |

---

## BookmarkTag

Junction table.

Purpose:

Many-to-many relationship between bookmarks and tags.

Attributes:

| Field       | Type |
| ----------- | ---- |
| bookmark_id | UUID |
| tag_id      | UUID |

Primary Key:

(bookmark_id, tag_id)

---

# 5. Relationships

## User → Bookmark

Relationship:

1:N

One user can own many bookmarks.

Each bookmark belongs to exactly one user.

---

## User → Collection

Relationship:

1:N

One user can create multiple collections.

---

## Collection → Bookmark

Relationship:

1:N

One collection can contain multiple bookmarks.

---

## Bookmark → Tag

Relationship:

N:N

Implemented through BookmarkTag.

---

# 6. AI Metadata Storage

The system stores AI-generated information directly in the Bookmark table.

Current fields:

- summary

Future fields may include:

- keywords
- relevance_score
- embedding_id

---

# 7. Future Semantic Search Design

Future versions will support semantic search.

Technology:

pgvector

Planned table:

BookmarkEmbedding

Attributes:

| Field       | Type      |
| ----------- | --------- |
| id          | UUID      |
| bookmark_id | UUID      |
| embedding   | VECTOR    |
| created_at  | TIMESTAMP |

Purpose:

Store vector embeddings generated from bookmark content.

This enables similarity search and recommendations.

---

# 8. Indexing Strategy

Planned indexes:

User:

- email

Bookmark:

- user_id
- collection_id
- created_at

Tag:

- name

Future:

- vector index on embeddings

---

# 9. Data Integrity Rules

Users:

- email must be unique

Bookmarks:

- URL cannot be empty

Collections:

- collection name must not be empty

Tags:

- duplicate tag names are not allowed

BookmarkTag:

- duplicate relationships are not allowed

---

# 10. Security Considerations

Passwords are never stored in plain text.

Only hashed passwords are persisted.

User data isolation is enforced through ownership validation.

Each user can only access their own data.

---

# 11. Future Database Evolution

Potential future additions:

- Shared collections
- Team workspaces
- Browser extension synchronization
- Recommendation engine
- Bookmark activity history

The database structure is designed to accommodate these features without major redesign.
